# 测试执行说明

每次新增或修改功能都要测试。先根据下表选择套件，完成后记录命令、结果和未验证边界。公共层变更必须覆盖其依赖模块，不能只验证页面能打开。

## 首次准备

Windows x64、Node.js 22.12+：

```powershell
npm ci
npm run test:fixtures
npm test -- --suite all
```

fixtures 命令在 `work/fixtures/` 生成样例，并下载公开 DOC/PPT/PPTX 测试文件。需要网络的只有依赖安装和样例准备，应用运行和测试预览均在本机完成。不要把私人文件放入可提交的样例目录。

## 集中执行与选择

PDF 性能专项：`npm test -- --suite pdf`。除了既有滚动、缩放、目录与打印权限检查，还验证高倍率预览单画布不超过 600 万像素、虚拟页/缩略图离开后再次出现能重绘；搜索单测覆盖 120 页共 2400 处命中且文本缓存不超过 32 页。不以开窗基准的单次波动宣称性能提升百分比。

PDF 交互专项：`npm test -- --suite pdf`。放大 PDF 后用真实中键拖动及空格加左键拖动，断言横向/纵向滚动位置变化；检查缩略图尺寸档位、拖动侧栏、重新挂载后的重绘；含多章节书签的样例跳到第 3 页，检查目录当前项自动高亮并滚进可见区域；选择文字后添加高亮和备注，检查旋转与标签切换后仍在，关闭文件再打开则清空。此套件不会连接实体打印机，也不会打包。

PDF 画布内存优化：`npm test -- --suite pdf`。80 页样例来回跳到第 40、80 页时，每次均检查画布包含已绘制像素；400% 缩放时检查所有活动页面的单画布不超过 600 万像素，同时验证页面仍可见。缩略图离开 DOM 后返回也要重新绘制。仅修改 PDF 模块时不做其他格式的全量测试。

PDF 三项定位修复：仅修改 `src/modules/pdf/` 时运行 `npm test -- --suite pdf`。80 页横竖交替样例分别跳到第 40、80 页，检查真实页面顶边与滚动容器的距离；搜索命中检查背景可见、叠加文字透明；含内链的双页样例验证旋转与适配后文字、链接坐标更新，点击链接仍跳到第二页。测试还对照查看 `outputs/verification/pdf-search-nav.png` 与 `pdf-rotated-link.png`。其他格式未改动时无需全量回归。

内存与长列表：unit 确认已选择文件仅携带元数据，打开可见标签时才读取字节；bulk 确认多文件仅挂载一个预览组件。printing 确认折叠行不创建纸张预览，同时保留批量设置与打印布局验证。共享预览容器变更按矩阵运行 all，测试不向实体打印机提交任务。

视觉布局：`npm test -- --suite visual`。真实 Electron 窗口以 960×640 内容尺寸、125% 页面缩放检查 PDF、DOCX、Excel、PPTX、图片、Markdown、JSON 的白天/黑夜界面，PDF/文本展开搜索后检查工具栏控件未被裁切，内容区域仍可用，并保存截图与布局指标至 outputs/verification。页面缩放用于模拟密集布局，不等同于完整 Windows DPI/多显示器验收。`FILE_PREVIEW_VISUAL_AUDIT=1` 仅生成优化前截图，不执行新布局断言。修改公共样式后运行 all；禁止将 audit 模式结果当作布局回归通过。

独立打印窗口与每文件参数：printing 套件检查打印入口策略（本窗口全部 PDF / 仅当前 / 不自动加入）、窗口非模态且可缩放、原窗口没有遮罩、原页/纸张尺寸显示；两文件以 A5/指定页和 A4/两份分别提交，未勾选文件不打印，应用到全部复制而不共享可变设置。检查点击文件名切换预览、预览关闭后重建、重复打开同一 Tab 不重复添加、“并排查看”窗口不重叠。仅模拟实体打印出口，不实际出纸。

文件数量限制回归：`npm test -- --suite bulk,printing`。bulk 通过文件选择入口打开 13 个标签并创建 26 个独立预览窗口；printing 验证一次添加 13 个 PDF 后批次保留全部 15 项。只验证取消固定数量限制，不代表可以超出机器内存无限加载文件；不向实体打印机提交这些批量样例。

沉浸全屏与页面适配：`npm test -- --suite immersive`。验证真实窗口进入全屏且首页不受影响，内容区域占满视口，Esc 退出恢复状态；PDF/Word/PPT/图片分别切换适合宽度、整页适配，检查宽高比不变。修改公共布局时仍运行 all。

PDF 打印：`npm test -- --suite printing`。测试拦截打印机枚举与实体打印入口，不会向打印机发送任务；真实隐藏窗口完整渲染打印页，再用 Chromium 在内存生成 PDF，检查 A5 的 148 × 210 mm 纸张、页数、指定源页、批量任务及无效页码不提交。其他格式不得出现打印按钮。基础测试还检查 A5 横纵向尺寸、范围解析、选项校验与纸张排版示意画布。

PDF 搜索/导航与 Excel 虚拟滚动：`npm test -- --suite pdf,excel`。pdf 覆盖搜索命中高亮、目录/缩略图侧栏；excel 覆盖跳到表尾后 DOM 行数有界、回顶后首行恢复。

性能基准（不计入 all）：`npm run bench`（pdfjs/xlsx 库级）与 `npm test -- --suite bench`（Electron 打开→ready 中位数写入 outputs/bench/）。

长 PDF DOM：模块测试断言 `.pdf-page` 数量有界（虚拟化占位 + 上下 pad），跳转末页仍可绘制；不再要求 80 个页节点同时在 DOM。

安装/卸载验收（不连打印机）：
```powershell
npm run build:win
npm run verify:install
# 卸载后：
npm run verify:install -- --expect-absent
```
Open With 仍按 TESTING 手工步骤在资源管理器验证；自动化只查安装目录与可选注册表。

打印手工验收：在有打印机的测试机选择 A4/A5、横纵向、黑白/彩色、单面/双面及不同份数，确认驱动支持与实际出纸；检查多 PDF 顺序、失败后继续、停止后续任务、无打印机提示。已提交任务的取消在 Windows 队列验证。“已提交”不是实际出纸成功。超大文档需检查内存上限提示和按页码分批。安装包内打印资源也应进行同样的布局测试。

仅修改缩放输入提交时，可运行 `npm test -- --suite zoom`。该套件在真实文本预览窗口依次触发 input → Enter / blur，检查输入值和实际文字字号同时变化；覆盖回车、失焦、连续提交、25–400 边界、空值回退和小数取整。不能只设置 value 后触发 change，否则会漏掉数字输入的类型转换问题。修改格式渲染或缩放计算时仍按下方影响矩阵测试。

```powershell
npm test -- --suite core
npm test -- --suite ppt,pdf
npm test -- --suite word,excel
npm test -- --suite text,image
npm test -- --suite all
```

入口 `tests/run.ts` 先执行类型检查和生产构建，再运行基础逻辑测试与选择的 Electron 套件。不认识的套件名直接失败，不会静默跳过。仅在确认源码自最近构建后没有变动时，才可使用 `--skip-build`；测试文件本身每次都会重新编译。

主进程/预加载通过与产品相同的 `electron-dist/` 加载。测试使用独立的 `work/test-profiles/<pid>/` 设置目录，不修改开发者真实偏好。格式测试在真实 Electron 渲染窗口运行，结果写入 `outputs/verification/tests-<suite>.txt`，失败返回非零退出码并保存 failure.txt。

## 套件内容与成功标准

### 基础逻辑（每次都执行）

`tests/unit.ts`：缩放限制 25–400%、无效设置回退、设置字段白名单、中文 Windows 文件路径识别。未知字段不得写进设置对象。

### core：设置、窗口、标签、托盘、安全

文件：`tests/suites/core.ts`。

1. 首页内部品牌图标和文字已移除；系统标题为“文件预览”；旧宣传文案、只读标记和底部状态条不存在。
2. 设置中选择黑夜；文档根节点主题同步，preferences.json 只包含偏好字段，不包含路径或历史。
3. 多文件首次询问选择标签页；出现两个文件标签，选择被记住。
4. 切换、拖动排序、关闭标签；关闭后对应预览组件移除，其他标签仍存在。
5. 再次多选不重复询问；设置为独立窗口后创建两个窗口，默认最大化。
6. 预览窗口 × 直接关闭自己、不弹框、不影响其他窗口；首页首次选择隐藏到托盘，窗口隐藏而进程存活，再次关闭使用记忆选择。
7. 两个独立预览窗口通过 HTML DataTransfer 拖动文件标签并走真实 IPC：目标出现两个标签，倍率保留，空源窗口关闭；无效 ID 移动失败不影响目标已有文件。
8. 外网请求被拦截，session 非持久化，主进程已交付 payload 释放。

`tests/quit.entry.ts` 另起进程验证选择“退出软件”会真正结束应用。所有套件执行前后对已有样例计算 SHA256，预览、缩放和列宽调整不得改变源文件。基础检查还验证生成的 NSIS 注册只添加 Open With 候选，不改扩展名默认值或 UserChoice。

系统模态选择框在测试中替换返回值，以便自动化；真实对话框文案、按钮位置、托盘菜单操作还应按下方手工流程检查。

### word

文件：`src/modules/word/tests/e2e.ts`；样例 `document.docx`、`legacy.doc`、`broken.docx`。

检查 DOCX/DOC 内容、DOCX 表格边界控件；通过真实鼠标事件拖动列边界，单元格必须实际变宽；内容滚轮后倍率不变。自动从样例生成含分页符的 `pages.docx`，通过真实 Chromium 鼠标滚轮验证连续滚动，右下角输入 2 定位到第二页，上一页滚动返回。损坏文件必须显示明确错误。Word 分页依赖实际渲染页面，不伪造旧 DOC 页数。

### excel

文件：`src/modules/excel/tests/e2e.ts`；样例 `styled.xlsx`、`legacy.xls`、`table.csv`。

断言深蓝背景合并标题、百分比格式、列边界真实拖宽、滚轮不改倍率、滚动到底部自动追加第 201 行且前 200 行仍在、后续列组可访问第 105 列。不能把分页隐藏误认为数据丢失。

### ppt

文件：`src/modules/ppt/tests/e2e.ts`；样例 `presentation.pptx`、`legacy.ppt`。

两种格式分别检查 Shadow DOM 中至少两页同时存在且包含内容文本；真实鼠标滚轮使 scrollTop 增长而倍率仍为 100%，输入页码 2 滚动定位，上一页返回开头。保存截图，检查文字未被清洗丢弃、页面比例正常、应用 CSS 不影响幻灯片。复杂文稿必须补充对应最小样例，不能据此承诺所有 PPT 保真。

### pdf

首屏优化回归：PDF 滚轮测试固定 1000×700 窗口，避免高分辨率屏幕下短样例无溢出。模块测试生成 80 页横竖交替样例，验证总页数、尺寸补齐、末页跳转渲染与连续倍率提交；运行 pdf,immersive,printing。尚未建立真实大文件的前后耗时基准，不声明提速百分比。

文件：`src/modules/pdf/tests/e2e.ts`；两页样例 `document.pdf`。

检查两页容器同时存在及画布渲染；真实鼠标滚轮使 scrollTop 增长而倍率仍为 100%，输入页码 2 定位，上一页回到开头，自定义 137% 生效。页面占位保留，PDF 画布仅按附近可见范围渲染。修改渲染取消逻辑后，应快速连续滚轮和缩放，不能出现画布同时渲染错误。

### text / image

各模块 `tests/e2e.ts`。文本检查原文安全显示、JSON 格式化/无效 JSON 回退、Markdown 渲染；图片检查 PNG/SVG/JPEG/WebP/GIF/BMP 的实际解码。缺失的小型位图样例由图片测试自动生成。均检查滚轮不改变倍率或图片显示尺寸。黑夜模式检查图片背景没有亮色棋盘格，使用 #252a32 深灰，并保存截图。扩展某种编码或图片格式时，应在对应套件加入真实样例和断言。

## 安装包与 ZIP 验证

默认 `build:win` **只生成 NSIS 安装包**，完成后自动调用 `verify:release`：检查 EXE/NSIS 标识、应用载荷大小下限、blockmap 非空，通过后生成仅含安装包的 SHA256SUMS.txt。

需要免安装 ZIP 时：

```powershell
npm run build:win:zip   # 只出 ZIP，并校验 CRC 与 win-unpacked 一致性
npm run build:win:all   # 安装包 + ZIP，两者都校验
npm run verify:release -- --zip   # 对已有产物额外做 ZIP 校验
```

可单独运行 `npm run verify:release`（仅安装包）。截断安装包必须返回非零状态。此检查不是安装包所有字节的完整性证明；安装与启动验收仍必须执行。失败后旧校验清单不代表本次成功，以命令退出码为准。

```powershell
npm run build:win
npm run test:package
```

打包测试启动真实 EXE，通过文件路径参数打开文件，并检查另一个进程再次打开文件可交付现有应用；启动测试时使用独立设置目录。用于测试的调试端口仅由测试进程命令行启用，不写入应用配置。

安装手工验收（在测试机器上执行）：

1. 安装新版，确认桌面/开始菜单/系统窗口/托盘仍使用眼睛 logo，软件内容区左上角没有品牌图标和文字。
2. 右击 PDF、DOCX、XLSX、PPTX → 打开方式 → File Preview；第一次启动和已运行时分别检查。
3. 含空格、中文的路径也能打开；不得把默认 Office 关联强制替换。
4. 若发布了 ZIP：完整解压 ZIP，运行 EXE；手动“选择其他应用”指向 ZIP 内 EXE 也能打开文件。
5. 点击预览窗口 ×，仅该窗口关闭；点击首页 ×，依次验证取消、隐藏和退出，托盘菜单能恢复和彻底退出。
6. 重启后主题、关闭方式、多文件方式仍保留；不能恢复上次文件或显示最近路径。
7. 在页面内容与空白区域都连续滚动；跨过页面边界时页码跟随，倍率不变；输入页码及上下页按钮只滚动定位。
8. 将两个独立预览窗口并排，拖动一个窗口的文件标签到另一个窗口内部，验证合并与源窗口关闭；拖到桌面后取消，原标签保留；目标窗口关闭或移交失败不应移除源标签。
9. DOCX 表格拖宽后关闭重开，源文件不应发生变化。

## 新模块约定

2026-09-13 状态与兼容性回归：core 检查跨窗口文本编码；excel 检查工作表与临时列宽迁移。`tests/excel-fallback.ts` 模拟样式引擎拒绝已知有效 XLSX，断言数据保留且有降级提示，损坏 ZIP 仍报错；已接入 excel/all 测试入口。这是容错测试，不代表复杂 Office 排版保真。基础测试覆盖密码、损坏、缺失、权限提示与内部错误信息不外泄。修改了共享 view 契约，运行 all。

新建 `src/modules/<type>/index.ts`、`index.vue`、处理器、样式及 `tests/e2e.ts`，在模块注册表和测试注册表分别注册。样例生成逻辑属于开发测试；产品处理器不得写文件。每个修复用例写明触发条件和预期变化，避免只断言元素存在。
